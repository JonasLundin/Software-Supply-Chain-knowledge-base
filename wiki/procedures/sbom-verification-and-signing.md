# Summary

**Cryptographic Signing and Integrity Verification of SBOMs** is the essential security procedure that cryptographically binds an SBOM to its corresponding executable binary, firmware image, or container artifact[^slsa-framework]. Without cryptographic signatures, an SBOM provides no tamper resistance: an adversary who compromises a distribution server or build cache can easily substitute a benign-looking SBOM alongside a backdoored binary, blinding downstream security scanners.

By leveraging modern cryptographic standards—specifically the in-toto Attestation Framework, Dead Simple Signing Envelope (DSSE), and Sigstore keyless infrastructure—organizations can prove beyond doubt that an SBOM was generated by an authorized pipeline for the exact cryptographic digest of the software running in production.

```
+-----------------------------------------------------------------------------------------+
|                    Cryptographic SBOM Binding & Ingestion Pipeline                      |
+-----------------------------------------------------------------------------------------+
                                             |
                                             v
+-----------------------------------------------------------------------------------------+
|                                    Production Build                                     |
|  - Compiles Binary: sha256:4b22... (Target Artifact)                                    |
|  - Generates SBOM: sbom.cdx.json                                                        |
+-----------------------------------------------------------------------------------------+
                                             |
                                             v
+-----------------------------------------------------------------------------------------+
|                                    Cosign Attestation                                   |
|  1. Encapsulates SBOM into in-toto Statement (Subject: sha256:4b22...)                  |
|  2. Wraps into DSSE envelope                                                            |
|  3. Signs keylessly using Fulcio OIDC certificate                                       |
|  4. Publishes signature + inclusion proof to Rekor transparency log                     |
|  5. Pushes attestation layer (.att) directly to OCI registry                            |
+-----------------------------------------------------------------------------------------+
                                             |
                                             v
+-----------------------------------------------------------------------------------------+
|                           Production Admission Controller (Kyverno)                     |
|  - Intercepts Pod deployment                                                            |
|  - Verifies: (1) Image signed by trusted OIDC issuer, (2) Attested SBOM exists          |
|  - Denies admission if SBOM is missing, modified, or signed by unauthorized identity    |
+-----------------------------------------------------------------------------------------+
```

# Technical Scope / Normative Requirements

### 1. The SBOM Substitution Attack Vector

In an unverified supply chain, an attacker alters the application code (e.g. injecting malicious telemetry into an npm library) but leaves the public SBOM untouched. Scanners inspecting the SBOM detect zero vulnerabilities. To defeat this attack:
- The SBOM must be signed as a predicate over the cryptographic hash of the compiled artifact.
- Any discrepancy between `hash(running_binary)` and `subject.digest` in the attestation invalidates the signature.

### 2. Normative Standards

- **Envelope Format**: Dead Simple Signing Envelope (DSSE) conforming to RFC specifications.
- **Statement Model**: in-toto Statement v1 (`_type: "https://in-toto.io/Statement/v1"`).
- **Predicate Type**: `https://cyclonedx.org/bom` or `https://spdx.dev/Document`.
- **Public Ledger Verification**: Valid entry in the Rekor transparency log with signed timestamp proof.

# Applicability & Operational Impact

- **Software Producers**: Fulfills NIST SP 800-218 task PS.2 ("Provide a mechanism for verifying software release integrity") and CISA Self-Attestation Clause 1 requirements.
- **Platform Security & SRE**: Enables zero-trust deployment gates in Kubernetes, OpenShift, and cloud container environments.
- **Software Consumers**: Empowers automated procurement intake pipelines to mathematically verify provenance before allowing binaries into internal repositories.

# Practical Implementation

### Step 1: Attesting the SBOM with Cosign

In a CI runner with OIDC permissions (e.g. GitHub Actions `id-token: write`):

```bash
# Attest CycloneDX SBOM to a container image digest
cosign attest --yes \
  --type cyclonedx \
  --predicate sbom.cdx.json \
  registry.acme.com/apps/payment-service@sha256:4b227777d4dd1fc61c6f884f48641d02b4d121d3fd328cb08b5531fcacdabf8a
```

### Step 2: Attesting an SBOM to an On-Premises File or Tarball

For non-containerized binaries (e.g. desktop installers or firmware):

```bash
# Generate keyless in-toto attestation for a standalone binary
cosign attest-blob \
  --yes \
  --type cyclonedx \
  --predicate firmware-sbom.cdx.json \
  --output-signature firmware-v1.att.json \
  firmware-v1.bin
```

### Step 3: Verifying the SBOM Attestation

Consumers or deployment gates verify that the attestation is authentic and untampered:

```bash
# Verify attestation identity and Rekor entry
cosign verify-attestation \
  --type cyclonedx \
  --certificate-identity "https://github.com/acme/payment-service/.github/workflows/release.yml@refs/heads/main" \
  --certificate-oidc-issuer "https://token.actions.githubusercontent.com" \
  registry.acme.com/apps/payment-service@sha256:4b227777d4dd1fc61c6f884f48641d02b4d121d3fd328cb08b5531fcacdabf8a \
  | jq -r .payload | base64 -d | jq .predicate > verified-sbom.json
```

### Step 4: Enforcing Deployment via Kyverno Policy

```yaml
apiVersion: kyverno.io/v1
kind: ClusterPolicy
metadata:
  name: require-attested-sbom
spec:
  validationFailureAction: Enforce
  rules:
    - name: check-image-sbom-attestation
      match:
        any:
          - resources:
              kinds:
                - Pod
      verifyImages:
        - imageReferences:
            - "registry.acme.com/apps/*"
          attestations:
            - type: https://cyclonedx.org/bom
              issuer: "https://token.actions.githubusercontent.com"
              subject: "https://github.com/acme/*"
              conditions:
                - all:
                    - key: "{{ regex_match('CycloneDX', '{{ payload.bomFormat }}') }}"
                      operator: Equals
                      value: true
```
