# Summary

**SLSA v1.2** is an approved specification from the OpenSSF establishing granular, verifiable security levels for software artifact generation and source control integrity[^slsa-spec-v1-2].

# Multi-Track Architecture
SLSA v1.2 divides supply chain requirements into distinct verification tracks:

### 1. Build Track
- **Build L1**: Provenance exists; the build process automatically generates unverified provenance indicating the build parameters and top-level inputs.
- **Build L2**: Hosted build service; provenance is generated by an authenticated build service preventing unilateral tampering by the software author.
- **Build L3**: Hardened build platform; the build platform enforces strong isolation between builds and generates non-falsifiable provenance with cryptographic verification of the builder identity. Note that Build L3 focuses on build platform trust and isolation; it does not mandate full bit-for-bit reproducible or hermetic builds.

### 2. Source Track
- **Source L1 (Version Controlled)**: Source code is managed in a version control system with changelog history.
- **Source L2 (Verified History & Provenance)**: Commits carry authenticated contributor identity and immutable history.
- **Source L3 (Continuous Technical Controls)**: Strict branch protection and automated enforcement preventing direct unverified modifications.
- **Source L4 (Two-Party Review)**: Mandatory independent code review by at least two distinct trusted reviewers prior to integration.
